这道题的核心不是“破解随机数”，而是：**加密过程对密钥是线性的，服务又允许你选择明文，因此每一次查询都能直接反推出一段 FLAG。** 随机偏移只打乱了片段顺序，没有阻止泄露。

## 1. 加密算法

核心代码在 `C:/Users/wangq/PycharmProjects/YulinSec--WriteUp--2026/scripts/破镜重圆/server.py:17`：

```python
r = secrets.randbelow(len(KEY))
prev = 0
for i, value in enumerate(pt):
    current = value ^ prev ^ KEY[(i + r) % len(KEY)]
    ct.append(current)
    prev = current
```

其中：

- `KEY = FLAG.encode()`：FLAG 本身就是密钥。
- `L = len(KEY)`：密钥长度。
- `r`：每次查询重新生成的随机偏移，范围是 `0 ~ L-1`。
- `prev`：前一个字节的密文，初始为 `0`。
- 输入只能是 `1~4` 个大写英文字母。

第 `i` 个字节的加密公式是：

\[
C_i=P_i\oplus C_{i-1}\oplus K_{(i+r)\bmod L}
\]

规定：

\[
C_{-1}=0
\]

这里使用了类似“密文链接”的结构：当前密文还会影响下一个字节。但这并不能保护密钥，因为前一个密文也是攻击者能看到的。

例如明文为 `AAAA`，随机偏移对应的密钥片段为 `Yuli`，加密结果是：

```text
明文： 41 41 41 41
密钥： 59 75 6c 69    即 Yuli
密文： 18 2c 01 29
```

## 2. 为什么能直接反推出密钥？

异或运算最重要的性质是：

\[
a\oplus a=0,\qquad a\oplus0=a
\]

并且满足交换律、结合律。因此把加密公式两边同时异或上 \(P_i\) 和 \(C_{i-1}\)，就得到：

\[
K_{(i+r)\bmod L}=C_i\oplus P_i\oplus C_{i-1}
\]

这正是 `recover_window()` 所做的事情，见 `C:/Users/wangq/PycharmProjects/YulinSec--WriteUp--2026/scripts/破镜重圆/exploit.py:29`：

```python
prev = 0
for p, c in zip(pt, ct):
    key.append(c ^ p ^ prev)
    prev = c
```

继续用上面的例子验证：

```text
18 ^ 41 ^ 00 = 59 = 'Y'
2c ^ 41 ^ 18 = 75 = 'u'
01 ^ 41 ^ 2c = 6c = 'l'
29 ^ 41 ^ 01 = 69 = 'i'
```

于是，每次发送 `AAAA`，都能恢复出一个形如：

```text
KEY[r], KEY[r+1], KEY[r+2], KEY[r+3]
```

的连续四字节片段。由于下标对 `L` 取模，它还可能跨越 FLAG 首尾，例如：

```text
c{xx
{xxx
xxxY
xxYu
xYul
```

`AAAA` 并不是必须的，任何已知明文都可以。选择它只是为了简单、固定，并确保通过输入检查。

**所以第一步攻击实际上已经完成了：每次查询不是“猜密钥”，而是精确计算四个密钥字节。**

## 3. 随机偏移为什么没用？

随机偏移让攻击者不知道：

> 这次得到的四个字符，分别位于 FLAG 的什么位置？

例如多次查询可能得到：

```text
Yuli
nSec
ulin
Sec{
ec{x
```

虽然顺序被打乱了，但这些片段之间存在 **3 字节重叠**：

```text
Yuli
 ulin
  linS
   inSe
    nSec
     Sec{
```

因此可以把每个四字节片段看成一个图里的边：

```text
前三个字节 --第四个字节--> 新的三字节状态
```

例如：

```text
Yul --i--> uli
uli --n--> lin
lin --S--> inS
```

脚本在 `exploit.py:41` 建立的就是这个重叠关系：

```python
nxt[w[:3]].add(w[3])
```

也就是：

```python
nxt[b"Yul"].add(ord("i"))
nxt[b"uli"].add(ord("n"))
```

## 4. 为什么需要已知前缀？

片段只能提供“谁可以接在谁后面”，还需要一个起点。题目 FLAG 格式提供了：

```text
YulinSec{
```

脚本从这个前缀开始，取当前结果的最后三个字节，寻找可以衔接的片段：

```python
for b in sorted(nxt.get(bytes(cur[-3:]), ())):
    dfs(cur + bytes([b]))
```

假设当前已经拼出：

```text
YulinSec{
```

最后三个字节是 `ec{`。如果样本中存在：

```text
ec{A
```

就可以追加 `A`；接着再用 `c{A` 查找下一段，直到遇到 `}`。

这就是 `assemble()` 中的 DFS 搜索，见 `exploit.py:39`。它本质上是在一个“三字节重叠图”中寻找路径：

```text
已知前缀 → 不断追加一个字节 → 遇到 } → 得到候选 FLAG
```

`max_len=128` 用来避免环导致无限递归。若重复的三字节上下文对应多个后继，DFS 会尝试不同分支。

## 5. 单字节查询有什么作用？

脚本还交替发送了 `A`，见 `exploit.py:91`。此时只有一个字节：

\[
C_0=A\oplus K_r
\]

所以：

\[
K_r=C_0\oplus A
\]

对应：

```python
byte_counter[ct1[0] ^ ord("A")] += 1
```

因为 `r` 均匀随机，大量采样后，可以得到 FLAG 中各种字节的近似数量。例如：

```text
'e' 约占多少
'_' 约占多少
'1' 约占多少
```

拼接完成后，脚本比较候选 FLAG 的真实字节数量与采样估计值，见 `exploit.py:104`。

这只是一个**启发式校验**，不是严格证明：

- 采样次数不足时，估计会有误差。
- 即使字节多重集合一致，也不能唯一确定排列顺序。
- 脚本只打印 `MISMATCH`，不会因此拒绝候选结果。

## 6. 这份攻击思路是怎么推导出来的？

可以总结成下面这条思考链：

1. **写成数学公式**  
   不要先盯着 Python 代码猜，先明确 \(P,C,K,r\) 的关系。

2. **观察攻击者已知什么**  
   明文是自己选的，密文由服务返回，前一个密文也已知；公式里唯一未知的是密钥字节。

3. **把未知量单独移出来**  
   得到 \(K=C_i\oplus P_i\oplus C_{i-1}\)，发现无需暴力破解。

4. **观察一次查询能泄露多少**  
   最多输入四字节，因此每次得到连续四字节密钥片段。

5. **分析随机化破坏了什么信息**  
   `r` 只隐藏了片段位置，没有改变片段内容，所以问题转化为“乱序片段拼接”。

6. **利用 FLAG 格式补足缺失信息**  
   用 `YulinSec{` 确定起点，用 `}` 确定终点。

7. **选择数据结构**  
   四字节片段有三字节重叠，于是自然想到重叠图和 DFS，而不是排列所有片段。后者会产生巨大的组合量。

其中最关键的一步就是：**发现密文反馈项 \(C_{i-1}\) 不是秘密，可以直接消掉。**

## 7. 异或加密还值得学习哪些内容？

建议按下面的顺序学习：

| 主题             | 核心内容                             | 典型攻击或练习                                              |
| ---------------- | ------------------------------------ | ----------------------------------------------------------- |
| 单字节异或       | 所有明文字节异或同一个字节           | 只有 256 种密钥，暴力枚举并结合英文频率评分                 |
| 重复密钥异或     | 明文异或循环使用的多字节密钥         | Hamming 距离猜密钥长度、按列转置、逐列单字节破解            |
| 一次性密码本 OTP | 密钥与明文等长、真随机且绝不复用     | 理解为什么理论安全，以及复用后为什么失效                    |
| Many-time pad    | 多条密文复用同一密钥流               | \(C_1\oplus C_2=P_1\oplus P_2\)，练习 crib dragging         |
| 流密码与 CTR     | 密钥流和明文异或得到密文             | nonce/IV 复用、已知明文恢复密钥流、密文可篡改性             |
| CBC 模式         | 明文块与前一个密文块异或后再分组加密 | CBC bit-flipping、padding oracle                            |
| 认证加密 AEAD    | 同时提供机密性、完整性和真实性       | 学习 AES-GCM、ChaCha20-Poly1305，理解为什么不能只加密不认证 |

尤其要掌握这两个恒等式：

\[
C_1=P_1\oplus K,\qquad C_2=P_2\oplus K
\]

如果复用同一密钥流：

\[
C_1\oplus C_2=P_1\oplus P_2
\]

密钥被完全消去。这是大量异或类 CTF 题目的共同根源。

最后需要区分：

- **单字节异或、重复密钥异或**：适合学习，不是安全加密。
- **OTP、CTR、CBC 中的异或**：只是安全方案里的一个组成步骤。
- **实际应用**：优先使用成熟的 AEAD 算法，不要自行拼接异或、随机偏移和密文反馈。本题正说明了：**密码学随机数也无法补救会直接泄露密钥的数学结构。**
