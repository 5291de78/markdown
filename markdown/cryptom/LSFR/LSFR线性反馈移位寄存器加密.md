## 一、服务器在干什么：`generate_nostalgia_stream` 逐行拆解

对应 server.py 里的 `generate_nostalgia_stream`。

### 1. 底层是一个 256 位 LFSR

```
def lfsr_step(state):
    fb = (state & LFSR_TAP).bit_count() & 1
    return (state >> 1) | (fb << 255)
```

把 `state` 想象成一排 256 个格子（bit 0 在右端）。每一拍：

- **反馈位** `fb`：把抽头位置（`LFSR_TAP` 置位的地方：第 0、2、5、10 位）的格子取出来异或，得到 0 或 1；
- **移位**：整体右移一格，最右边那格被丢弃；
- **补位**：`fb` 塞进最左端（bit 255）。

```
拍 t:    [ fb ][ b255 ][ b254 ] ... [ b1 ][ b0 ]
                ↓ 右移，b0 丢弃，fb 补到左端
拍 t+1:  [ fb' ][ fb   ][ b255 ] ... [ b2 ][ b1 ]
```

关键性质：**这一步对 state 是 GF(2) 上的线性变换**（每一位的新值都是旧若干位的异或）。所以整个状态序列完全由初始 seed 决定，且每个状态位在任意时刻都是 seed 各比特的异或组合。

### 2. 滤波器：故意加非线性

如果直接输出 state 的某位，那输出就是 seed 的线性函数，高斯消元秒破。所以服务器过了一个**滤波函数**，每次吐出**两个**比特：

```
w = (state & W_MASK).bit_count()          # 选出一批格子，数有几个 1
wqf_plus  = ((w * (w + 1)) // 2) & 1      # C(w+1, 2) mod 2
wqf_minus = ((w * (w - 1)) // 2) & 1      # C(w-1, 2) mod 2
u_bit = ((state & T1_MASK).bit_count() & 1) ^ wqf_plus
v_bit = ((state & T2_MASK).bit_count() & 1) ^ wqf_minus
```

- `parity(T1 & state)` 是线性部分（T1 掩码选中的格子异或起来）；
- `C(w+1,2) mod 2` 是**二次部分**——它依赖于 `w`，而 `w` 是"有多少个格子同时为 1"，这是比特之间的乘积关系，不是异或关系。正是这个二次项让单路输出抗线性攻击（这就是论文 2025/2140 的 Weightwise Quadratic Filter 设计）。

### 3. 打包成字节

```
u_byte = (u_byte << 1) | u_bit
```

内层循环 8 次，每拍产生 u、v 各一位，先进来的在高位——所以**字节的 bit 7 是最早的一拍**。外层循环 36 次，共 288 拍，得到 U、V 各 36 字节。

然后这两个流被按 `(u_i, v_i)` 配对送进 Hill 加密（Stage 1 我们逆的就是这一步），所以你拿到 Hill 明文后，面前就是 U、V 两个字节流。

## 二、Stage 2 攻击原理：二次项是怎么被异或杀掉的

### 1. 核心代数事实

一拍内：

```
u = lin1 ⊕ C(w+1, 2)
v = lin2 ⊕ C(w-1, 2)
```

两路异或：

```
u ⊕ v = lin1 ⊕ lin2 ⊕ [C(w+1,2) + C(w-1,2)]
```

而组合数展开：**C(w+1,2) + C(w−1,2) = w²**。在 mod 2 下 `w² ≡ w`（0²=0，1²=1），所以二次项之和退化成 `w mod 2`——而 `w mod 2` 恰恰就是 `parity(W_MASK & state)`，**也是线性的**！

可以列个小表验证（只看 w mod 4）：

| w mod 4 | C(w+1,2) mod 2 | C(w−1,2) mod 2 | 和   | w mod 2 |
| ------- | -------------- | -------------- | ---- | ------- |
| 0       | 0              | 1              | 1    | 0...    |

等一下——注意 `w=0` 时和是 1 而 `w mod 2 = 0`？不对，mod 2 加法：C(w+1,2)+C(w−1,2) = w²，**作为整数**成立，所以 mod 2 下 `f+ ⊕ f- = w² mod 2 = w mod 2`。表里要按整数和再 mod 2：

| w mod 4 | f+   | f−   | f+⊕f− | w mod 2 |
| ------- | ---- | ---- | ----- | ------- |
| 0       | 0    | 1    | 1     | 0 ✗     |

`w=0`：C(1,2)=0，C(−1,2)……这里 `wqf_minus = ((w*(w-1))//2)&1`，w=0 时 `w*(w-1)=0`，f−=0。整数恒等式 C(w+1,2)+C(w−1,2)=w² 对 w≥1 成立（w=0 时 C(−1,2) 按广义定义是 1，但代码算的是 0·(−1)//2 = 0）。所以代码层面 w=0 时 f+⊕f−=0=w mod 2 ✓。正确的表：

| w    | f+ = C(w+1,2)&1 | f− = (w(w−1)/2)&1 | f+⊕f− | w&1  |
| ---- | --------------- | ----------------- | ----- | ---- |
| 0    | 0               | 0                 | 0     | 0 ✓  |
| 1    | 1               | 0                 | 1     | 1 ✓  |
| 2    | 1               | 0                 | 1     | 0 ✗? |

w=2：C(3,2)=3，&1=1；w(w−1)/2=1，&1=1，f−=1。f+⊕f−=0，w&1=0 ✓。

| w    | f+   | f−   | f+⊕f− | w&1  |
| ---- | ---- | ---- | ----- | ---- |
| 0    | 0    | 0    | 0     | 0    |
| 1    | 1    | 0    | 1     | 1    |
| 2    | 1    | 1    | 0     | 0    |
| 3    | 0    | 1    | 1     | 1    |
| 4    | 0    | 1    | 1     | 0 ✗? |

w=4：C(5,2)=10，&1=0；w(w−1)/2=6，&1=0，f−=0。f+⊕f−=0，w&1=0 ✓。（我手算容易错，但恒等式 w²=C(w+1,2)+C(w−1,2) 是代数事实，mod 2 后必然成立。）

**结论：**

```
u_bit ⊕ v_bit = parity((T1 ⊕ T2 ⊕ W_MASK) & state)
              = parity(MASK & state)        ← 纯线性！
```

这就是 solve 脚本里 `MASK = T1 ^ T2 ^ WM` 的由来（solve_nostalgic_weight.py）。

**设计者的失误**：两路滤波器共享同一个 `w`、用了一对"共轭"的二次函数，它们的 XOR 恰好退化成线性。单看一路是二次的，两路一起看就塌了。

### 2. 线性化之后：每个输出比特都是 seed 的线性方程

第 t 拍观测到 `obs_t = parity(MASK & state_t)`，其中 `state_t = Lᵗ(seed)`（L 是 `lfsr_step` 的线性变换）。

问题：`state_t` 我们不知道，方程是关于 state_t 的不是关于 seed 的。需要把掩码"回拉"到 seed 上。

**掩码回拉推导**（对偶技巧）：`parity(m & L(s))` 展开就是 `⊕ⱼ mⱼ·L(s)ⱼ`。看 L 干了什么：

- 新 bit j（j<255）= 旧 bit j+1 → 贡献 `mⱼ·sⱼ₊₁`
- 新 bit 255 = 旧抽头位的异或 → 贡献 `m₂₅₅·(s₀ ⊕ s₂ ⊕ s₅ ⊕ s₁₀)`

按 s 的各位重新收拢：`s_i` 的系数是 `m_{i-1}`（来自移位），再加上"如果 m₂₅₅=1 且 i 是抽头位则多一个 1"。也就是：

```
pb(m) = ((m << 1) & REG) ^ (TAP if m 的 bit255 为 1)
```

于是 `parity(m & L(s)) = parity(pb(m) & s)`，迭代 t 次：

```
obs_t = parity(pbᵗ(MASK) & seed)
```

**第 t 个观测比特 = seed 各比特的一个已知异或组合**。GF(2) 上的线性方程，系数向量就是 `pbᵗ(MASK)`，右端是 `obs_t`。

> 这里就是那个 `|` vs `^` 的坑：抽头位 {0,2,5,10} 可能和 `m<<1` 已有的置位重叠，GF(2) 里两项相遇是**异或抵消**，用 `|` 就把 1⊕1=0 算成 1 了。

### 3. 解方程

288 个观测比特（36 字节 × 8，注意字节内先出高位，对应脚本 `for b in range(7, -1, -1)`）给出 288 个方程、256 个未知数（seed 的每一位），超定，GF(2) 高斯消元唯一解出 seed。

脚本里 gf2_solve 的实现技巧：用一个 Python int 表示一整行——bit1~bit256 是 256 个系数，bit0 挂右端值；消元就是 `x ^= basis[pivot]`，全部是位运算，非常快。

### 4. 整条链路串起来

```
服务器:  seed ──LFSR+滤波──> U,V ──Hill──> hill_ct
攻击者:  hill_ct ──Stage1 逆Hill──> U,V ──⊕──> u⊕v 比特流
        ──每比特 = parity(pbᵗ(MASK) & seed)──> 288 个 GF(2) 方程
        ──高斯消元──> seed = (p+q) 的高 256 位 ──> 交给 Stage 3 连分数
```

seed 本身是 `p+q >> shift_bits`，所以 Stage 2 的真正战利品是 RSA 里 `p+q` 的高位——这就是通往 Stage 3 分解 N 的桥。

------

一句话总结 Stage 2：**两路二次滤波器因为共享重量 w 且二次项互为共轭，XOR 后塌缩成线性；LFSR 的线性性又让每个输出比特都能回拉成 seed 的线性方程；288 条方程高斯消元，seed 直接裸奔。**
