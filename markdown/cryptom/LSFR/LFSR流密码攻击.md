## O，前置

### O,流密码

流密码算法通常由异或运算、 与运算以及循环移位等基础操作组成， 这使得流密码算法具有加解密速度快， 软硬件实现简单等特点， 因此常被用于资源受限制的环境条件， 比如处理器性能较弱、 硬件资源有限。

对于流密码而言， 关键在于设计好的伪随机数生成器。一般来说， 密钥 流发生器生成的序列随机性越强， 其明文中的统计特征就会被覆盖的更好。 密钥流发生器的基本构造模块为反馈移位寄存器， 其主要包含线性反馈移位寄存器和非线性反馈移位寄存器。

### 1，基于LFSR的流密码

模仿一次一密加密过程，利用有限的key，生成无限的keystream密钥流：
$$k_0,k_1,\dots$$
密码学的攻击模型中，有一种叫做已知明文攻击。也就是，攻击者已知明密文对：
$$(p_1,c_1),(p_2,c_2),\dots,(p_m,c_m)$$
这个过程就是简单的异或运算，所以可得：
$$k_1 = p_1 \oplus c_1,\,k_2 = p_2 \oplus c_2,\dots,\,k_m = p_m \oplus c_m$$

此时便出现了两种解密方法。

**方法一：**
$$\text{从}k_1,k_2,\dots,k_m\text{中恢复初始密钥}$$

**方法二：**
从$k_1,k_2,\dots,k_m$中恢复某一时刻的中间状态$(s_0,s_1,\dots,s_{L-1})$。有了$(s_0,s_1,\dots,s_{L-1})$可以得到同样的密钥流。

结论：只通过LFSR生成密钥流是不安全的。Berlekamp-Massy算法可以利用$2L$长的输出序列，以$O(L^3)$的复杂度得到生成这个序列的线性反馈移位寄存器。

## 2,案例

```python
LFSR_TAP = (1 << 10) | (1 << 5) | (1 << 2) | 1
T1_MASK = 0x9E3779B97F4A7C15F39CC0605CEDC8341082276BF3A27251F86C6A11D0C18E95
T2_MASK = 0x6A09E667BB67AE853C6EF372A54FF53A510E527F9B05688C1F83D9AB5BE0CD19
W_MASK = 0x3C6EF372FE94F82BE73980C0B9DB906821044ED7E744E4A3F0D8D423A1831D2B
```



1，LFSR行为模拟

```python
def lfsr_step(state):
    fb = (state & LFSR_TAP).bit_count() & 1
    return (state >> 1) | (fb << 255)
```

TAP抽头函数对当前state的LFSR进行抽头计算popcount并mod2(因为&1就是保留最低位，也就是%2)，所以这个函数就是LFSR的状态转移函数

```
拍 t:    [ fb ][ b255 ][ b254 ] ... [ b1 ][ b0 ]
                ↓ 右移，b0 丢弃，fb 补到左端
拍 t+1:  [ fb' ][ fb   ][ b255 ] ... [ b2 ][ b1 ]
```

2，滤波器

```python
def generate_nostalgia_stream(seed, n_bytes=36):
    state = seed
    U_bytes, V_bytes = [], []
    for _ in range(n_bytes):
        u_byte, v_byte = 0, 0
        for _ in range(8):
            # Weightwise Quadratic Filter (ePrint 2025/2140)
            w = (state & W_MASK).bit_count()
            wqf_plus = ((w * (w + 1)) // 2) & 1
            wqf_minus = ((w * (w - 1)) // 2) & 1
            u_bit = ((state & T1_MASK).bit_count() & 1) ^ wqf_plus
            v_bit = ((state & T2_MASK).bit_count() & 1) ^ wqf_minus
            u_byte = (u_byte << 1) | u_bit
            v_byte = (v_byte << 1) | v_bit
            state = lfsr_step(state)
        U_bytes.append(u_byte)
        V_bytes.append(v_byte)
    return U_bytes, V_bytes
```

## 一、为什么需要滤波器：裸 LFSR 是透明的

先看没有滤波器会怎样。LFSR 每一步就是"抽头位异或 → 移位 → 补到最高位"。如果服务器直接输出 state 的某一位，那么每个输出比特都是 **seed 若干位的异或**。

异或就是 GF(2) 上的加法。也就是说每个输出比特都是关于 seed 的**一次方程**：

```
输出第 t 比特 = seed第3位 ⊕ seed第57位 ⊕ seed第201位   （系数已知）
```

攒够 256 个比特，就是 256 个一次方程解 256 个未知数，高斯消元直接出 seed。所以**纯 LFSR 没有任何安全性**。

要安全，输出函数必须**非线性**——必须出现比特之间的**乘法**，比如 `x₁·x₂`。因为在 GF(2) 上，`x₁·x₂` 没法写成任何"若干位异或"的形式（你可以拿 4 种取值试：00→0，01→0，10→0，11→1，没有线性函数能对上）。

**滤波器的作用**：LFSR 照常跑（保持线性、好分析、周期长），但输出前过一个非线性函数 `f(state)`，把线性性藏起来。这是流密码的经典结构（Grain 等真实密码都这么设计）。

## 二、题目里的滤波器：用"数 1 的个数"造乘法

看代码（server.py 的 `generate_nostalgia_stream`）：

```
w = (state & W_MASK).bit_count()          # ①
wqf_plus  = ((w * (w + 1)) // 2) & 1      # ② C(w+1, 2) mod 2
wqf_minus = ((w * (w - 1)) // 2) & 1      # ③ C(w,   2) mod 2
u_bit = ((state & T1_MASK).bit_count() & 1) ^ wqf_plus    # ④
v_bit = ((state & T2_MASK).bit_count() & 1) ^ wqf_minus   # ⑤
```

逐行拆：

### ① `w = (state & W_MASK).bit_count()`

`state & W_MASK`：掩码把不关心的位清零，只留下被 W_MASK 选中的那批格子。`.bit_count()` 数这批格子里有几个 1。

设被选中的位是 `x₁, x₂, ..., x_k`（每个 ∈ {0,1}），那么：

```
w = x₁ + x₂ + ... + x_k      ← 注意这是整数加法，不是异或
```

`w` 本身是个 0~k 的整数。这是整个滤波器的枢纽。

### ②③ 关键数学：C(w,2) 就是"所有比特对的乘积之和"

组合数 C(w,2) = w(w−1)/2 的含义是"从 w 个 1 里挑 2 个的方案数"。换句话说：

```
C(w, 2) = x₁x₂ + x₁x₃ + ... + x_{k-1}x_k = Σ_{i<j} xᵢ·xⱼ
```

**每一项都是两个比特的乘积——这就是二次项，就是非线性的来源。** 这个设计叫 Weightwise Quadratic Filter（按重量构造的二次滤波器），妙处是：不用逐对枚举比特（k 很大时项太多），只要数出 w 再算 w(w−1)/2 就得到了全部二次项的和。

拿小例子验证。假设 W_MASK 只选中 3 位 x₁x₂x₃：

| x₁x₂x₃ | w    | C(w,2) | x₁x₂⊕x₁x₃⊕x₂x₃ |
| ------ | ---- | ------ | -------------- |
| 000    | 0    | 0      | 0              |
| 001    | 1    | 0      | 0              |
| 011    | 2    | 1      | 1              |
| 101    | 2    | 1      | 1              |
| 111    | 3    | 3      | 3（mod 2 = 1） |

完全吻合。而 C(w+1,2) = C(w,2) + w，多出来的 `w` 是线性的（`w mod 2 = x₁⊕x₂⊕...⊕x_k`，整数和的奇偶性 = 各位异或）。所以：

```
f⁺ = C(w+1,2) mod 2 = [全部二次项] ⊕ [选中位的异或]     次数 2
f⁻ = C(w,  2) mod 2 = [全部二次项]                      次数 2
```

### ④⑤ 组装输出

```
u_bit = parity(T1 & state) ⊕ f⁺      一路：T1 掩码的线性项 + 二次项+w
v_bit = parity(T2 & state) ⊕ f⁻      另一路：T2 掩码的线性项 + 二次项
```

注意 `(...).bit_count() & 1` 就是"异或"：数出 1 的个数再看奇偶，等于把所有位异或起来。

所以每一拍，u 和 v 各自都是 state 的**二次函数**。单看任何一路，都是"线性部分 + 二次部分"，256 个一次方程的老办法解不动——这正是设计者想要的效果。

## 三、漏洞：两路一异或，二次项对消

设计败笔在于：**两路用的是同一个 w**（同一张 W_MASK、同一个 state），二次项在两路里长得一模一样。

异或两路输出：

```
u ⊕ v = parity(T1&s) ⊕ parity(T2&s) ⊕ f⁺ ⊕ f⁻
```

而（整数恒等式）：

```
f⁺ + f⁻ = C(w+1,2) + C(w,2) = w(w+1)/2 + w(w-1)/2 = w²
```

mod 2 下 `w² ≡ w`（0²=0、1²=1），所以：

```
f⁺ ⊕ f⁻ = w mod 2 = parity(W_MASK & s)     ← 二次项没了，只剩线性！
```

逐项对照表（代码语义）：

| w    | f⁺=C(w+1,2)&1 | f⁻=C(w,2)&1 | f⁺⊕f⁻ | w&1  |
| ---- | ------------- | ----------- | ----- | ---- |
| 0    | 0             | 0           | 0     | 0 ✓  |
| 1    | 1             | 0           | 1     | 1 ✓  |
| 2    | 1             | 1           | 0     | 0 ✓  |
| 3    | 0             | 1           | 1     | 1 ✓  |
| 4    | 0             | 0           | 0     | 0 ✓  |
| 5    | 1             | 0           | 1     | 1 ✓  |

直观理解：**C(w+1,2) 和 C(w,2) 共享全部"对乘积"项**（C(w+1,2) = C(w,2) + w，只是多了个 w），两路异或时这些二次项出现两次，GF(2) 里 1⊕1=0，全部抵消，只剩下那个一次项 w。

合并三处线性项：

```
u ⊕ v = parity(T1&s) ⊕ parity(T2&s) ⊕ parity(W_MASK&s)
      = parity( (T1 ⊕ T2 ⊕ W_MASK) & s )          ← 一张掩码搞定
```

异或的分配律：`parity(A&s) ⊕ parity(B&s) = parity((A⊕B)&s)`（对应位上两个线性函数相加，等于掩码先异或再取奇偶）。所以脚本里才有：

```
MASK = T1 ^ T2 ^ WM
```

**攻击者拿到 Hill 解出的 U、V 流后，逐比特异或，就得到了一个纯线性系统的输出**——滤波器的二次保护形同虚设。之后就是上次讲的：掩码回拉把每个比特写成 seed 的线性方程，288 个方程 GF(2) 消元，seed 出炉。

## 四、一句话总结

- **加密侧思路**：LFSR 提供长线性序列，滤波器用 C(w,2) 注入"比特对乘积"这种二次非线性，挡住线性方程攻击；双通道 u/v 输出是论文 2025/2140 的设计。
- **攻击侧突破**：两通道共享同一个 w，且 f⁺、f⁻ 的二次部分完全相同，`u ⊕ v` 时二次项两两抵消，系统从二次塌回一次——防御全部白搭。
- **修补启示**：如果两路用不同的 W_MASK（不同的 w₁、w₂），或者二次函数不共轭，这个抵消就不成立。所以这不是"滤波 LFSR 不能双通道"，而是"两个滤波器不能共享同一个可约的二次结构"。
