## 2，.C文件的编译过程

## 	#1预处理（preprocess）		.i 文本文件 gcc ....-E

- 展开 `#include`，把头文件内容全部粘贴进来

- 替换 `#define` 宏(define做的是***查找--替换*** ， 比较危险)

- 删除注释

- 处理条件编译 `#ifdef` / `#endif`

- 输出：`.i` 文本文件，还是 C 语法

## #2编译（compile,C-->汇编）	.s汇编文本 gcc ...-S

  - **词法分析、语法分析、语义检查** 
  - 生成抽象语法树 AST（抽象语法树abstracted syntax tree），做优化

抽象语法树的列表怕就是抽象语法地图（ASM)l了

```latex
赋值表达式
├─ 左值：变量 a
└─ 右值：加法表达式
   ├─ 操作数：常量1
   └─ 操作数：常量2
```

  - 翻译成汇编指令

```
#【行号】 【汇编指令】 【可选注释】
	.file	"2binary.c"
	.text
	.section .rdata,"dr"
.LC0:
	.ascii "Hello World\0"
	.text
	.globl	main
	.def	main;	.scl	2;	.type	32;	.endef
	.seh_proc	main
main:
	pushq	%rbp
	.seh_pushreg	%rbp
	movq	%rsp, %rbp
```



## #3汇编（assemble，汇编-->机器码） 

## 															.o目标文件 gcc...-c

- 将汇编指令逐条翻译成 CPU 可识别的二进制机器码

- 生成**目标文件 .o**

  > `.o` 结构：机器指令段 (.text)、全局数据 (.data)、符号表、重定位表。
  >
  > (文件已经是二进制的了,IDE下将会看到乱码)
  > 
  > (此时还不能运行，因为调用外部函数（比如`printf`）地址是空的)

## #4链接（link, 目标文件 -- > 可执行文件)  .exe文件

- 合并多个 `.o` 的段（代码段、数据段）
- 符号解析：找到未定义符号（如 printf）
- 重定位：修正函数调用地址，把空白处填上真实地址
- 链接系统库（libc）

# 3CPU架构

 ### ***#1指令集架构（Instruction Set Architecture，ISA）***

它是 CPU 硬件和软件之间的契约 / 接口标准

**对于软件而言，它规定了**

1. 有哪些指令（加法、跳转、内存读取、函数调用等指令有哪些）
2. 寄存器有多少个、叫什么、多少位宽
3. 指令编码规则：一条指令翻译成二进制机器码是什么格式
4. 内存寻址方式、中断、异常怎么处理
5. 函数调用约定等规则

**对于硬件而言，它就是指令字典**

## #2主流架构

|          架构          | 代表                                     | 特点                       |
| :--------------------: | ---------------------------------------- | -------------------------- |
| x86-64 （也叫 AMD64）  | Intel、AMD 的 CPU，绝大多数 Windows 电脑 | CISC，指令复杂，长度不固定 |
| ARM64 （也叫 aarch64） | 苹果 M 系列芯片、手机芯片                | RISC，指令精简，长度固定   |

## #3汇编风格

> 对于x86-64架构而言主要有两种风格 **Intel** vs **AT&T**

它们描述的是 **同一套机器码** ，**只是写法不一样**，就像中文和英文描述同一件事。

最核心的区别：**操作数方向相反**

```asm
;Intel 风格
mov  rax, rbx        ; 把 rbx 的值 → 送到 rax
; 目的操作数, 源操作数
;AT&T 风格
movq  %rbx, %rax     ; 把 rbx 的值 → 送到 rax
; 源操作数, 目的操作数
```
