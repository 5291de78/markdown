## 1,程序是如何调用函数的？

一般情况下，计算机执行一条指令时，根据程序计数器（PC）中存放的指令地址，将指令由内存取到指令寄存器中（IR）。程序按照顺序依次执行，程序计数器加一指向下一条语句。

但当发生函数调用(func_call)时（call,是一条特殊跳转语句，打断PC正常自增)

PC便指向所调用函数的第一句执行语句的地址，此时的自增便在函数体内自增……

如果有一个函数foo其原型为int foo (int arg1, int arg2, int arg3);函数调用栈向上增长，较小编号的内存地址在顶部

**计算机主要依赖函数调用栈帧来完成函数调用的完整过程**，栈帧空间主要靠esp和ebp两个寄存器指针来标记，函数参数、局部变量、返回值也都存储在栈帧空间中，用于函数的访问。

### 详细过程：

ESP寄存器被被调函数用来指向栈顶。EBP寄存器充当“基指针”

首先，main将EAX、ECX和EDX寄存器的内容压入栈。这只是一个可选步骤，只有在需要保留这三个寄存器的内容时才会执行。

接下来，main将foo的参数一个接一个地，最后一个参数首先压入栈。

最后，main可以发出子程序调用指令

执行调用指令时，EIP寄存器的内容被压入栈。由于EIP寄存器指向main中的下一条指令，因此效果是返回地址现在在栈顶。调用指令执行后，下一个执行周期从名为foo的标签开始。

当函数foo，即被调用者，获得程序的控制权时，它必须做三件事：设置自己的栈帧，为局部存储分配空间，并根据需要保存EBX、ESI和EDI寄存器的内容。

因此，首先foo必须设置自己的栈帧。EBP寄存器当前指向main栈帧中的一个位置。这个值必须被保留。所以，EBP被压入栈。然后ESP的内容传输到EBP。这允许参数作为EBP的偏移量来引用，并释放了栈寄存器ESP以做其他事情。

接下来，foo必须为其局部变量分配空间。它还必须为其可能需要的任何临时存储分配空间。例如，foo中的一些C语句可能包含复杂的表达式 。子表达式的中间值必须存储在某个地方。这些位置通常称为临时的，因为它们可以被下一个复杂表达式重用。

现在，局部变量和临时存储可以作为基指针EBP的偏移量来引用。

最后，foo必须在需要时保存EBX、ESI和EDI寄存器的内容。如果在foo的开始时将这些寄存器的原始值压入栈，那么原始值可以从栈上弹出，如果ESP寄存器指向图4中显示的正确位置。因此，在foo主体的执行期间不要丢失栈指针ESP非常重要——即，push和pop的数量必须平衡。

现在可以执行函数foo的主体了。这可能涉及将东西压入和弹出栈。因此，栈指针ESP可能会上升和下降，但EBP寄存器保持固定。这很方便，因为这意味着我们可以始终将第一个参数作为[EBP + 8]来引用，不管在函数中进行了多少次push和pop。

foo函数的执行也可能涉及其他函数调用，甚至对foo的递归调用。然而，只要在这些调用返回时恢复EBP寄存器，就可以继续将参数、局部变量和临时存储作为EBP的偏移量来引用。

在将控制权返回给调用者之前，被调用者foo必须首先安排将返回值存储在EAX寄存器中。我们已经在上文中讨论了如何将返回值超过4字节的函数调用转换为带有额外指针参数的函数调用，并且没有返回值。

其次，foo必须恢复EBX、ESI和EDI寄存器的值。如果这些寄存器被修改了，我们在foo的开始时将它们的原始值压入了栈。原始值可以从栈上弹出，如果ESP寄存器指向图4中显示的正确位置。因此，在foo主体的执行期间不要丢失栈指针ESP非常重要——即，push和pop的数量必须平衡。

程序控制权返回到调用者，main应该保存返回值，该返回值被放置在EAX中。

最后，如果函数调用之前在栈上保留了EAX、ECX和EDX寄存器的值，main函数可以弹出这些寄存器的值。这将使栈的顶部恢复到我们开始整个函数调用过程之前完全相同的位置。

## 2，函数执行完毕后怎么返回的

发生函数调用（func_call)时，PC会先存储下一条执行语句的指令地址，再执行call跳转到函数体内，函数调用结束（PC指向return执行语句时）时，程序会返回到主调函数中调用函数的语句的后一条语句继续执行。换句话说，也就是“从哪里离开，就回到哪里”。

------



## 3,寄存器在其中起到什么作用？

**EAX（RAX）累加器**：函数返回值存放于此；被调用者可以随意破坏该寄存器（caller‑saved 调用者保存寄存器）。

**ECX、EDX**：调用者保存寄存器；被调用函数可以随意改写，如果 caller 要保留原值，调用前必须手动压栈保存。

**EBX、ESI、EDI**：被调用者保存寄存器（callee‑saved）；如果被调用函数修改了它们，必须在函数开头 push 入栈，ret 之前 pop 恢复原值，不能直接破坏。

### 函数调用栈

函数调用栈是一块管理函数调用顺序的计算机内存区域。

当一个函数（callee）被调用时，函数的参数、局部变量和返回地址等信息会被保存在栈内存中，同时函数执行完成后，这些信息会被弹出栈，控制权将返回到（caller）调用该函数的地方。

函数调用栈在程序执行过程中主要管理函数调用的顺序，确保程序的执行是有序的并能正确返回到调用函数的地方

### 函数栈帧

**函数栈帧是函数调用栈中的一个单元**，**它主要存储一个函数执行过程中所需的信息**。每当一个函数被调用时，**一个新的函数栈帧会被创建并被推入函数调用栈的顶部**，当函数执行完毕后，对应的函数栈帧会被弹出并释放。

函数栈帧通常包含以下主要部分：

返回地址：函数执行完毕后应该返回的地址，方便程序控制流回到正确的位置。
参数：传递给函数的参数值，存储在栈帧中，方便函数可以访问和操作这些参数。
局部变量：函数内部定义的局部变量会被存储在栈帧中，在函数执行期间被访问和修改。

### 调用过程

如果有一个函数`foo`，其原型为：

```c++
int foo (int arg1, int arg2, int arg3);
```

并且foo有两个局部整型变量（假设int的大小为4字节），那么栈在调用foo并且程序控制权仍在foo函数内部时，栈向上增长，较小编号的内存地址在顶部。

ESP寄存器被foo用来指向栈顶。EBP寄存器充当“基指针”。由main传递给foo的参数和foo中的局部变量都可以作为基指针的偏移量来引用。

这里使用的约定是，被调用者（callee）在返回之前可以破坏EAX、ECX和EDX寄存器的值。因此，如果调用者（caller）想要保留EAX、ECX和EDX的值，调用者必须在调用子程序之前显式地将它们保存在栈上。

另一方面，被调用者必须恢复EBX、ESI和EDI寄存器的值。如果被调用者对这些寄存器进行了更改，被调用者必须在栈上保存受影响的寄存器，并在返回之前恢复原始值。

传递给foo的参数被压入栈中。最后一个参数首先被压入，所以最后第一个参数在栈顶。foo声明的局部变量以及临时变量都存储在栈上。

4字节或更小的返回值存储在EAX寄存器中。如果需要超过4字节的返回值，则调用者将传递一个“额外的”第一个参数给被调用者。这个额外的参数是应存储返回值的位置的地址。也就是说，在C语言中，函数调用：

```c++
x = foo(a, b, c); //可以转换为
foo(&x, a, b, c);
```

当函数foo，即被调用者，获得程序的控制权时，它必须做三件事：设置自己的栈帧，为局部存储分配空间，并根据需要保存EBX、ESI和EDI寄存器的内容。

因此，首先foo必须设置自己的栈帧。EBP寄存器当前指向main栈帧中的一个位置。这个值必须被保留。所以，EBP被压入栈。然后ESP的内容传输到EBP。这允许参数作为EBP的偏移量来引用，并释放了栈寄存器ESP以做其他事情。

## 汇编指令

以下是函数调用过程中主要用到的汇编指令，理解这些指令的作用，才能深入理解函数调用的执行机制。

mov a, b：把b中的数据赋值给a
call：将返回地址（当前指令后的地址）入栈，rsp递减
ret：从栈中弹出返回地址，rsp递减，将这个地址赋值给rip，程序会从新地址继续执行
push：压栈，rsp递减
pop：出栈，rsp递增

## *寄存器基础知识

以下是函数调用过程中主要用到的寄存器

**eax、rax：accumulator累加器**

存储操作的结果，也用来存放函数返回值
**ebx、rbx：base基址寄存器**

存放基地址
**ecx、rcx：counter计数器**

常用来控制循环次数
**ebp、rbp：存放栈底地址**

base pointer
**esp、rsp：存放栈顶地址**

stack pointer
**edi、rdi、esi、rsi：变址寄存器**

配合完成数据的赋值操作，参数传递的默认寄存器
