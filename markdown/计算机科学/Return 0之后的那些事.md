# Return 0之后的那些事

```
操作系统加载可执行文件
      │
      ▼
CRT 启动函数（Windows: mainCRTStartup / Linux: _start）
      │  ① 初始化栈、全局/静态变量（C++ 还要跑构造函数）、准备 argc/argv
      ▼
你的 main() 函数
      │  ② return 0;  ← 返回到 CRT，而不是操作系统
      ▼
CRT 收尾清理（见下方 5 步）
      │  ⑤ 调用系统调用真正结束进程
      ▼
操作系统：exit_group(Linux) / ExitProcess(Windows)
      │  ⑥ 回收资源、把状态码交给父进程
      ▼
Shell / 构建系统拿到退出码
```

## return 之后，CRT 的标准化清理顺序
1. **逆序销毁 main 里定义的局部 static 对象** （C++，只针对 main 内的）。
2. **逆序调用`atexit()` /`at_quick_exit()` 注册的函数** ——你平时"退出前关日志、释放资源"的钩子就在这里执行。这就是"main 都 return 了，atexit 函数却还能跑"的原因。
3. **逆序销毁所有全局/静态对象** （所有带非平凡析构函数的全局对象、命名空间作用域静态对象）。
4. **刷新并关闭 C 标准流`stdout` /`stderr` /`stdin**` ——所以你`printf` 的东西即使没加`\n` ，退出时也会被 flush 出来。
5. **删除`tmpfile()` 创建的临时文件** 。

之后，CRT 调用系统调用`exit_group` （Linux）或`ExitProcess` （Windows），把`0` 这个退出码传给内核，操作系统再销毁进程的所有资源（内存、文件描述符等其实都会由内核回收）。

## 为什么要理解这层"中转"
文章开头列的几个"怪现象"，根子都在这里：

- **为什么 main 结束了进程还在跑？** ——因为还有别的线程没结束，或 CRT 清理还没走完（`exit_group` 要等所有线程）。
- **为什么 return 之后全局对象才析构？** ——因为析构发生在 CRT 收尾阶段，不是 main 里。
- **退出码去哪了？** ——Linux 下`echo $?` 能看到；CI/CD、脚本、Docker 健康检查、构建系统都靠它判断成败（0=成功，非 0=失败）

|        动作         |              本质              |             是否触发清理              |
| :-----------------: | :----------------------------: | :-----------------------------------: |
|      return 0       |    函数级返回，把值交给 CRT    |            发完整收尾流程             |
|       exit(0)       | 直接进程级终止，跳过 main 返回 |        同样触发`atexit` 等清理        |
| `abort()` /_exit()` |            强制终止            | 不 做清理（不跑 atexit、不 flush 流） |





# 思考

怎么解释这个程序不能保存int a？

```c
#include<iostream>
using namespace std;
int a = 0;
int main(){
    cout<<a<<"\n";
	cin>>a;
    cout<<a<<"\n";
    return 0;
}
```

1 .`a` 存在哪里？`a` 是全局变量，存在进程的 数据段 （内存 RAM 里）。`cin >> a` 只是把内存里这个字节改了。

2. 程序结束后它去哪了？`system("pause")` 结束 →`main` 返回`return 0` → CRT 收尾 →`exit_group` /`ExitProcess` → 操作系统销毁整个进程、回收它的全部内存 。所以`a` 这块内存被收回，值蒸发。

3. exe 文件本身没被改过 你双击 exe，操作系统只是把 exe 文件 读进内存 执行，并不会把你的输入写回 exe 文件。运行程序 ≠ 修改程序文件。所以下次再运行，磁盘上的 exe 还是老样子。

4. 为什么下次运行又变回 0？ 因为`int a = 0;` 是 初始化语句 。每次程序被加载，CRT/加载器都会按 exe 里存的数据把这个全局变量重新初始化为 0。它没有"上次运行"的记忆。
